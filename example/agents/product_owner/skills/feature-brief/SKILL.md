# Feature brief

Turn the request into a decision the planner can implement. Identify the user, problem, desired outcome, constraints, and priority. Separate confirmed requirements from assumptions and open questions.

Write acceptance criteria as observable behavior, including important error or empty states where relevant. State exclusions only when they prevent a likely scope misunderstanding. If a tradeoff affects the user experience, present options in product terms and get the user's decision.

Send the agreed brief and later scope decisions to the planner. Do not infer architecture or file changes from the brief.
